## Empfehlung

Hinweis: Mit dem Maßstab "Server-SLA mit echter Gutschrift" liegt nur OVHcloud (99,99 % Instanz), AWS (99,99 % nur mit zwei AZ) und IONOS/OTC (99,95 %, unsicher) über Hetzner (99,9 %). SLA-Gutschriften sind aber nur Geldrückgabe, keine Verfügbarkeit. Für ein Projekt dieser Größe zählt Architektur mehr als der SLA-Prozentwert.

### Setup A: ein Anbieter, zwei Standorte
**Hetzner Cloud, Falkenstein plus Nürnberg** (beide Deutschland, 99,9 % je Server, ISO 27001).
- Zwei Server mit Placement Group, Forgejo-Daten per `restic` oder Forgejo-Dump auf den jeweils anderen Standort und auf eine Storage Box, tägliche Hetzner-Backups (+20 %), Floating IP oder DNS-Failover mit kurzer TTL.
- Aufwand: Einrichtung etwa 1 bis 2 Tage, danach etwa 1 bis 2 Stunden pro Monat (Updates, Restore-Test vierteljährlich). Failover ist manuell oder per Skript. Rechenleistung hat die Seite selbst praktisch nie nötig.
- Alternative bei Wunsch nach C5 und höherem SLA: **IONOS Cloud (Frankfurt plus Berlin)**, Aufwand ähnlich, Preis höher (unsicher).

### Setup B: Anbieter plus Cloudflare davor
**Statische Seite auf Cloudflare Pages/Worker (oder Hetzner-Origin hinter Cloudflare)**, Forgejo und Runner auf Hetzner (oder netcup, günstiger, SLA nur 99,6 %).
- Cloudflare liefert CDN, WAF, DDoS und bleibt auch bei Origin-Ausfall im Cache erreichbar. Origin-IP nur für Cloudflare freigeben, Zugriff auf Forgejo über Cloudflare Access oder Tunnel.
- Aufwand: etwa 1 Tag Einrichtung, danach unter 1 Stunde pro Monat. Der Datenschutzaspekt (US-Konzern, AVV und Standardvertragsklauseln nötig) ist zu bewerten.
- Passt zum Projekt am besten: Die Besucherseite hängt dann nicht am eigenen Server, nur Git und CI.

### Gesamteinschätzung
Für "echter Server mit Redundanz" lautet die Rangfolge: Setup B (günstig, robust, wenig Pflege), dann Setup A mit Hetzner. Bei Behörden- oder Compliance-Druck: STACKIT oder T Cloud Public (C5), Preise vor Entscheidung einholen.
