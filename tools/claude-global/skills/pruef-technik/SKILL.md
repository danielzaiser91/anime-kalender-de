# Prüftechnik (aus der Auftragsvorlage, 20.10.2026)

Ergänzt die Klasse K1 in `bauer.md`/`pruefer.md`; Anlässe stehen in `lehren.md`.

- **Basislauf zuerst:** Jede Mutationsprobe beginnt mit einem grünen Lauf des unveränderten Codes. Scheitert der Aufruf selbst (z. B. `npx` im Pfad mit Leerzeichen), sind alle Mutanten scheinbar rot; tsx direkt über `node node_modules/tsx/dist/cli.mjs`. `node --require` braucht einen Pfad mit `./` (`--require ./tools/bestand-sperre.cjs`), sonst MODULE_NOT_FOUND (Bauer 2017, 25.10.2026). Tests im eigenen Format (`pruefe(…)`, z. B. `tools/*.test.mjs`) laufen mit `node <datei>` und melden über den Exit-Code; `node --test` zählt dort nichts und lässt jeden Mutanten überleben (Prüfer 2293, 28.10.2026). Läuft die Probe in Kopien von `tools/`, kann schon die unveränderte Kopie rot sein (Bauer 2539, 31.10.2026: 12 Rote nur durch die Kopierumgebung) — dann eine unmutierte Kontrollkopie mitfahren und nur Rote zählen, die über die Kontrolle hinausgehen.
- **Kein Zeitlimit um ein Mutationsskript (21.10.2026, Prüfer 1394):** `timeout` bricht mitten in einer Mutation ab und lässt die Quelldatei mutiert zurück. Auch das Zeitlimit des Bash-Werkzeugs (~5 min im Vordergrund) bricht so ab (Prüfer 2288, 28.10.2026). Mit `run_in_background` ohne Frist starten, Fortschritt in eine Logdatei, danach `git status` der berührten Dateien. Eine überlebende Mutation an einer Normalisierung (z. B. `adressKern`) schließt ein Testfall mit zweiter Schreibweise derselben Kennung.
- **Zurücksetzen nur aus einer Kopie (24.10.2026, Dirigent 1917):** Hat die Datei ungespeicherte eigene Änderungen, setzt `git checkout -- <datei>` nach einer Mutante auch diese zurück. Vor der ersten Mutante die Datei ins Scratchpad kopieren, jede Mutante aus dieser Kopie zurückholen, danach `git diff --stat` lesen. Einfacher (zweiter Fall 25.10.2026, 1991): vor der ersten Mutante ein WIP-Commit, dann setzt `git checkout -- <datei>` nur die Mutante zurück.
- **Mutationsanker und Parallelläufe (21.10.2026, Prüfer 1739):** Anker samt Anführungszeichen setzen (`"ak-saal"` statt `ak-saal`, sonst trifft er `ak-saal-vorhang`) und mit `replaceAll` ersetzen; vor dem Lauf prüfen, dass der Anker genau einmal bzw. erwartbar oft vorkommt. Nie zwei Mutationsläufe auf dieselbe Datei gleichzeitig — Sperrdatei neben dem Skript oder nacheinander.
- **Mutante muss greifen (Bauer 2037, 25.10.2026):** Ein `sed`-Mutant, dessen Muster nicht trifft, ändert still nichts und „überlebt“ mit Exit 0. Mutationen per Skript, das nach dem Ersetzen `geändert: true` ausgibt (Ausgabe ≠ Eingabe), sonst gilt der Mutant als nicht gelaufen; Muster mit Backslash sperrt der Hook ohnehin, dort das Edit-Werkzeug nehmen und die Mutante mit `git diff` belegen (2516, 31.10.2026). Ebenso muss der Testfall den Auslöser wirklich treffen (Kommentar *im* Eintrag, nicht daneben).
- **Formeln:** Jede Variable einer Formel einzeln mutieren, nicht nur Vergleichsoperatoren (`- start` überlebt, wenn kein Test mit start > 0 läuft). Bei einem Vergleich `f(a) !== f(b)` wird jede Seite einzeln mutiert, und jede braucht ihren eigenen Testfall (28.10.2026, 2281: „ BD“ nur am deutschen Titel getestet, die englische Seite überlebte).
- **Sonderzeilen in die Mitte:** Ein Testfall für Zeilen, die übersprungen werden (Kommentar, Leerzeile, Kopf), steht zwischen zwei Datenzeilen, nie am Rand — am Listenanfang überlebt das Entfernen des Filters (25.10.2026, PR 2018).
- **Gegenfall ohne Nebenwirkung (Bauer 2044, 25.10.2026):** Ein Gegenfall muss vor der Änderung belegt unberührt bleiben; eine Prime-Meldung als Gegenfall bekam selbst einen Termin und verdeckte das Ergebnis. Erst den Gegenfall allein laufen lassen, dann einsetzen.
- **Test-Fixture verdeckt den Zweig (Bauer 2341, 29.10.2026):** Liefert das Testpaket schon, was der neue Code ergänzen soll, oder schluckt ein `catch` im Prüfling den Fehler, bleiben Mutanten grün (10 von 17). Je Zweig eine Fixture, in der nur dieser Zweig das Ergebnis erzeugt, und ein Fall, in dem der `catch`-Weg sichtbar anders ausgeht.
- **Nachgebildeter Anzeigetext (Bauer 2047, 25.10.2026):** Ein Test, der einen Text aus dem Code nachbildet, prüft per `quelle.includes(…)`, dass es ihn dort noch gibt — sonst testet er eine Fassung, die nie angezeigt wird („für“ statt „fuer“ blieb grün).
- **Grenzen:** Jede Vergleichsgrenze (`>`, `>=`, `> 1`) bekommt schon in R1 einen Testfall genau auf der Grenze.
- **Standardwert hinter einer Umgebungsvariable (Prüfer 2034, 25.10.2026):** Setzen alle Tests eine Überschreibung (`WT_WURZEL`, `AK_*`), ist der Standardwert ungetestet; er bekommt eine eigene Pflicht-Mutation und einen Test ohne die Variable — gerade wenn der PR genau diesen Standardpfad ändert.
- **Neue Exporte:** Jede neu exportierte Funktion bekommt eine eigene Mutation an ihrer Ausgabe, auch wenn Tests ihr Ergebnis sonst von außen einsetzen (`traegerJeSeite` „nur der letzte Träger“ blieb grün).
- **Mutationsliste:** Der Bauer legt sie selbst an, je `filter(`, `&&` und Vergleich eine, bevor der Prüfer kommt. Behauptet ein PR „der Test fängt X“, wiederholt der Prüfer die Mutation selbst und übernimmt keine Zahl des Bauers. Jeder Mutant ersetzt genau eine Stelle: Das Skript zählt die Treffer des Ankers und bricht bei mehr als einem ab (21.10.2026, 1759: ein Mutant traf die Zwillingsfunktion statt der neuen). Nimmt eine Auswahllogik mehrere Eingabeformen an (Text, Objekt, Hauptfall), bekommt jeder Zweig einen eigenen Mutanten, sonst bleibt ein ungetesteter Zweig unbemerkt (ticket-board PR 26, 25.10.2026). Je Weiche (`if`, `||`, `?:`) und je Glied einer Schlüsselmenge ein eigener Mutant; „gleichwertig“ erst behaupten, wenn jeder dieser Mutanten gelaufen ist (Bauer 2023, 25.10.2026: Ein-Zeilen-Ersetzungen entlang der eigenen Testfälle ließen 14 von 38 überleben). Ein Parser mit Nachschlagetabelle (Monatsnamen, Kürzel) oder Zeichenklasse (`[~„"]`, Trenner; 2286: `~` und End-Trenner ohne Fall) braucht einen Testfall je Tabelleneintrag, sonst überlebt jede Mutation eines ungetesteten Eintrags (28.10.2026, PR 2284: 7 von 12 Monaten ohne Fall). Eine Vorrangregel („Datum schlägt Titel“) braucht einen Widerspruchsfall an echten Daten, in dem beide auf verschiedene Ergebnisse zeigen; vor dem PR misst der Bauer die Bilanz main gegen PR auf allen lokalen Rohdaten, je Aufrufer der geteilten Funktion (2284 R3: ADN und folgen-anker fehlten) (28.10.2026, 2284: 23 von 24 richtigen Titeltreffern wären durch eine Woche Datumsversatz falsch geworden). Liegt nur eine echte Seite vor, gehört ein Belastungstest dazu (Teil der Eingaben stumm schalten), denn erst er zeigt, ob ein Rückfallweg falsch statt offen zuordnet. Jedes Mutationsskript lässt zuerst die unmutierte Kontrolle laufen und bricht ab, wenn sie rot ist (2284: Kontrolle des Bauers war rot, weil `shared/` in der Kopie fehlte).
- **Pflicht-Mutant „Aufruf entfernt“ (2635, 01.11.2026):** Ein neuer Wächter-Block in einem `check-*.ts` bekommt neben den Mutanten der Lib-Funktion immer „Aufruf entfernt“ und „Bedingung false“ am Aufrufer, gefangen von einem Prozesstest über das echte Skript (Wegwerf-Kulisse per `AK_ROOT`); 2635 R1 deckte nur die Lib, der Aufrufer-Mutant überlebte.
- **Trenner im Mutationsskript:** nie `|` zwischen Anker und Ersatz, er kollidiert mit `||` im Code; ein ASCII-Zeichen wie `#` nehmen, das im Code nicht vorkommt, und den Anker im Log mitdrucken — `§`/`¦` sind Mehrbyte, `read` mit `IFS` zerlegt sie bytegenau, der Anker wird leer und jeder Mutant sieht „rot“ aus (Prüfer 1403, 21.10.2026; Bauer 2024, 25.10.2026).
- **Oberflächen:** Bilder mit dem längsten vorkommenden Wert (Anbieter-, Sender-, Titelname) und mit der breitesten Systemschrift: „≈ 17:00“ brach in einer 44-px-Spalte nur mit Segoe UI um, Roboto passte (Bauer 2025, 25.10.2026). Textbreite per `Range` auf den Inhalt messen, nicht per Augenmaß.
- **Datenzugriff (Prüfer):** Wer konnte die berührten Daten vorher lesen, wer nachher?
- **Rückrechnung (Prüfer):** Eine neue Ableitungsregel (errechnete Termine, Folgenzahlen, Zuordnungen) wird an allen Fällen des Datensatzes rückwärts nachgerechnet; richtig/falsch je Abweichung zählen (PR 1292: 32 von 51 falsch, erst die Rückrechnung zeigte es).
- **Bedrohungsmodell bei Wächtern:** Der Auftrag nennt, welche Umgehungen in Scope sind (Versehen von Mensch oder Agent) und welche nicht; der Prüfer übernimmt das Modell wörtlich, statt Schreibweise um Schreibweise zu runden.
- **Kein Wächter ist, wer nur nachrechnet (Bauer 2549, 31.10.2026):** Ruft ein Bestandswächter dieselbe Funktion wie der Bau auf einer Kopie der Daten auf und vergleicht mit deren Ergebnis, ist er tautologisch; er prüft das Ergebnis gegen festgehaltene echte Fälle (Soll aus Beleg, nicht aus dem Code).
- **Zählzeile im Bau-Log braucht einen Abgriff (Prüfer 2549, 31.10.2026):** Jede Zeile, die Verworfenes zählt, wird im Test über Log oder Rückgabe geprüft; der Mutant „Zählzeile übersprungen“ (`if (!n) return` → `return`) muss rot werden.
- **Dateiscanner-Wächter (Prüfer 2196, 27.10.2026):** Neben den Selbstfällen der Erkennungsfunktion gehören `main` (ein geplanter Treffer muss Exit ≠ 0 geben) und die Bereichsliste in die Mutationsprobe. Eine Gesamt-Mindestzahl an Dateien fängt keinen weggefallenen Ordner und keine weggefallene Endung; deshalb je Ordner und je Endung mindestens eine Datei verlangen.
- **Daten nur über einen Lader (Bauer 2614, 01.11.2026):** Gilt eine Datei nur gefiltert (Streichliste o. ä.), ist der Standardwächter ein Allowlist-Scanner: jeder Leser der Rohdatei außerhalb des Lader-Moduls und einer benannten Ausnahmeliste ist rot (Vorbild `pipeline/lib/anisearch-rohleser.ts`); Mutante „ein Leser auf roh umgestellt“ muss rot werden.
- **Quelltext per Regex lesen (25.10.2026):** Ein Wächter oder Test, der eine Liste aus `.ts`-Quelltext per Regex zieht, importiert sie stattdessen, wo das geht. Ein Lookahead wie `(?![^}]*repo:)` ließ Einträge still fallen, sobald `repo:` in einem Kommentar stand (PR 2037).
- **Attrappen protokollieren `process.cwd()`** (und ihre Argumente) in eine Sonde, die der Test prüft: eine stumme Attrappe macht die Mutation „Aufruf im falschen Ordner“ unsichtbar (PR 1689 R2, 20.10.2026).
- **Komponenten-Handler ohne DOM-Bibliothek testen:** eine Sonden-Komponente rendert den echten Baum per `renderToStaticMarkup`, fängt die Props (onClick, onChange) ab und ruft sie im Test auf — so ist die Verdrahtung belegt, nicht nur die reine Funktion dahinter (Bauer 1912, 24.10.2026).
- **Rot belegen, nicht nur Exit-Code:** Jede Mutante zuerst mit `node --check` bzw. `tsc --noEmit` auf Syntax prüfen und beim Lauf die letzte Fehlerzeile mitprotokollieren — sonst kann „rot“ ein Syntaxfehler sein (PR 1680 R2, 20.10.2026). Rot selbst nach Exit-Code zählen, nicht nach einem Fehlerzeichen: die Wächter schreiben `✖`, nicht `✗` (Zählen auf `✗` ergab 0 rot, Prüfer 2301, 28.10.2026).
- **Je Zieldatei ihr Test:** Ein Mutationsskript ordnet jeder mutierten Datei den zuständigen Test zu; ein Test für alle lässt Mutanten fremder Dateien scheinbar überleben (Prüfer 1689 R3, 20.10.2026).

- **Aufrufseiten mitmutieren (Prüfer 1698 R2, 20.10.2026):** Wird Logik in eine reine Funktion ausgelagert, mutiert die Probe auch jede Aufrufseite — Argumente (`springe(-1)` → `springe(1)`), durchgereichte Werte (`clientWidth` → `0`, `matches` → `false`) und jede `onClick`-Verdrahtung von Callback-Props. Die gedeckte Funktion belegt nicht, dass sie richtig aufgerufen wird.
- **Zähler vor einer Aktion (Bauer und Prüfer 1853, 23.10.2026):** Bucht ein Riegel (Rate-Limit, Kappe, Sperre) vor der Aktion, braucht der Test den Fall „Aktion scheitert oder wirft → Zähler wieder frei“; sonst sperrt ein Versandfehler den Nutzer still. Bei B4 (`/push/abo`) und `/restore` mitprüfen.
- **Zähler auf offenen Pfaden (Bauer und Prüfer 1856, 23.10.2026):** Ein Zähler auf einem Pfad ohne Anmeldung braucht eine Tagesobergrenze für Zufallseingaben (Schreibverstärkung: 100.000 Zufalls-Token im Test), und Zustand, der über ein `await` lebt, einen Parallelfall mit verzögerter Attrappe (50 gleichzeitige Abrufe → genau ein Stapel). Tests prüfen Grenzen mit festen Zahlen, nicht mit der importierten Konstante, sonst überleben ±1-Mutanten.
- **Löschexperiment (25.10.2026, Prüfer 1741):** Für „kein Leser übersehen“ Pfade löschen und Prüfungen vorher/nachher vergleichen: `node tools/loeschexperiment.mjs <pfad…> [--pruefung <npm-skript>…] [--cache]` (Näheres `docs/wissen/betrieb.md`, Abschnitt Löschexperiment); nur in einem Worktree ohne eigene Änderungen an den Pfaden. Ein Löschwerkzeug wird zusätzlich mutiert an Signal-Abbruch (Handler mit `process.exit` überspringt `finally`), am Pfad, der eine Junction enthält, und an skip-worktree-Dateien (`git ls-files -v`), Prüfer 1983, 25.10.2026.
- **Git-Werkzeuge: Löschfall mit committeter Datei, Filter mit Gegenfall (Prüfer 2696, 02.11.2026):** Ein Löschfall mit einer nie committeten Datei prüft `--diff-filter` nicht; der Test committet erst, löscht dann. Jeder Ordner- oder Dateifilter bekommt einen Fall knapp außerhalb (z. B. `scripts/x.ts`), und jeder Zähler einen Fall mit mehr als einem Treffer.
- **Parser fremder Seiten: jede Einstiegsseite als Fixture (25.10.2026, PR 1955):** Liest Code eine fremde Seite (Amazon, Netflix …), braucht der Test je Seitenvariante, von der der Nutzer kommt (Abo-, Kauf-, Kanalfassung), eine eigene Fixture — die Uncut-Fixture allein verdeckte, dass das Prime-Logo auf der Kauf-Seite als Kanal galt. Prüfer verlangt die fehlende Variante, bevor er freigibt. Ändert der Fix eine Vorrangregel (Text vor Logo), bleibt jeder alte Test der Gegenrichtung stehen oder wird mit Beleg ersetzt (1991: „Logo vor Prime“ fiel still weg).
- **Pixelwächter: Vergleichspunkte nur aus Zonen ohne Überlagerung (25.10.2026, PR 1993):** Ein Messpunkt relativ zum Element (z. B. 19 px diagonal über der Ecke) kann auf einem Verlauf, Badge oder Text liegen, den nur manche Fälle zeigen — Wackler 1/40. Vor dem Wählen nachsehen, was dort gezeichnet wird, und mit dem Fall messen, der die Überlagerung hat.
- **Mutationsschleife nur auf gesichertem Stand (Bauer 2520, 31.10.2026):** Vor einer Schleife mit `git checkout HEAD -- <datei>` prüfen, dass `git log -1` den WIP-Commit enthält und `git status` sauber ist; ein am Hook gescheiterter Commit (Fehler von `| tail` verschluckt) ließ die Schleife die eigenen Edits verwerfen. Commit-Ausgabe nie abschneiden.
- **Ausnahmen in einer Aufrufsuche sind die Lücke (Prüfer 2521, 31.10.2026):** Schließt eine Suche „wer ruft X auf“ eine Klasse aus (Tests, Konfigurationen, Globs, Template-Pfade), prüft der Test genau diese Klasse: ein fremder Test, `vite.config.ts` oder `tools/*bild*` in einem Workflow ist ein Aufrufer. Dazu eine Eigenschaftsprüfung über den Bestand.
- **Gecachter Zustand und neue Fixtures (Bauer 2521, 31.10.2026):** Baut ein Test einen Index (Kette, Map, Cache) einmal vorab, sehen später angelegte Fixtures ihn nicht, und der Fall bleibt still grün oder falsch; je Fixture-Satz den Index neu bauen und eine Gegenprobe sichern, dass der Fall den neuen Index wirklich nutzt.
- **Mutante ohne Diff zählt nicht (Prüfer 2525, 31.10.2026):** nach jedem Einsetzen `git diff --quiet` prüfen und „KEIN DIFF“ ausgeben; sed-Quoting erzeugt sonst stille Null-Mutanten, die grün „überleben“.
- **Zeilenzustand braucht zwei Körperzeilen (Bauer 2591, 01.11.2026):** Ein Wächter, der über Zeilen Zustand führt (Heredoc, mehrzeilige Zeichenkette, Blockskalar), bekommt Testfälle mit mindestens zwei Körperzeilen; mit nur einer überlebt der Mutant „Zustand endet sofort“.

**Kein `commit -q` vor `reset --soft HEAD~1` (Bauer 2532, 31.10.2026):** Ein still gescheiterter Commit lässt das folgende `reset --soft HEAD~1` einen fremden Commit abhängen. Nach jedem Hilfs-Commit `git log -1 --format=%s` prüfen und erst dann zurücksetzen; Reparatur über `git reflog`.

**Mutationsskript räumt `.orig`-Reste selbst weg (Bauer 2526, 31.10.2026):** Wer Mutanten per Kopie `datei.orig` einsetzt, stellt im `finally` zurück und löscht die Kopie; vor dem Commit `git status --short | grep orig` muss leer sein.

**Rückrechnung vergleicht Ergebnisse, nicht Zwischenelemente (Prüfer 2532, 31.10.2026):** Bei Gleichstand (gleiches Datum) wählen alt und neu verschiedene Elemente mit gleichem Termin; verglichen wird der erzeugte Termin (Beginn, Ende, Status), sonst entstehen Scheinabweichungen.

- **Frist-Mutation (31.10.2026, PR 2533):** „Frist ignoriert“ überlebt, solange kein Testfall einen Befehl hat, der nach der Frist anders endet als in ihr — je Frist einen solchen Fall anlegen.

- **Mutationsläufer nie mit `--test true` (Prüfer 2540, 31.10.2026):** Ohne echten Testbefehl gibt es kein Rot-Signal, der Läufer läuft minutenlang und blockiert die Shell.
