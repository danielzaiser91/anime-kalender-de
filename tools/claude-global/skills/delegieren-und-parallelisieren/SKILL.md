## Zerlegungsregel für den Leitagenten

- **Parallel** nur bei getrennten Dateien/Modulen (kein gemeinsamer Schreibpfad, keine Abhängigkeit der Ergebnisse). Jeder Teilbauer bekommt einen eigenen Worktree. Teilen sich zwei parallele Aufträge eine Ansicht oder Datenquelle, nennt jeder Auftrag den anderen PR samt gemeinsamer Quelle und verlangt den Zusammenspiel-Testfall von Anfang an (2297/2298, 28.10.2026).
- **Nacheinander**, wenn ein Teil die Ausgabe des anderen braucht oder beide dieselbe Datei, dieselbe generierte Datei (`public/data/*`) oder dieselbe Funktion berühren. Im Zweifel nacheinander.
- **Hängt ein Auftrag an einem PR, prüfe ich vor dem Start `state == MERGED`** (`gh pr view N --json state`), nicht „Merge gesetzt“: Auto-Merge kann am CI-Prüfer hängen bleiben (14.10.2026: Bauer wartete 30 min auf einen offenen PR und endete ohne Arbeit). Sonst bleibt der Auftrag im Vorrat. Vor jedem Start aus einer Vorratsdatei zusätzlich `gh pr list --state merged --search '<stichwort>'` — 30.10.2026 lief ein Bauer auf einen Auftrag, den PR 2386 zwölf Stunden vorher erledigt hatte.
- **Worktrees** legt der Leitagent an (über `isolation: worktree` seiner Bauer) und räumt sie nach der Zusammenführung auf; ungenutzte Reste meldet er.
- **Konflikt:** Er löst keinen Inhaltskonflikt still. Er meldet Dateien, beide Seiten und seinen Vorschlag; entscheiden tue ich.
- Er meldet **einen** Bericht: Diff-Überblick (Dateien, Zeilen), Prüfergebnis je Teil, offene Punkte. Zusammengeführt wird in einen Ergebniszweig/PR, nie auf main.

```

  Gut gelaufen: <was wiederholbar gemacht werden sollte>
  Schlecht gelaufen: <was Zeit kostete oder schiefging, mit Ursache>
  Unerwartet: <was anders war als im Auftrag angenommen>
  Vorschlag: <konkrete Änderung an Werkzeug, Skill, Regel, Auftragsvorlage — auch außerhalb des Auftrags: Performance, Stabilität, Effizienz, Last-Ort, Ideen (Skill `prueftisch`, „Nebenbei beobachten“); mit Zahl, Untergrenze, Nutzen>
```

## Technik

- `run_in_background`, nie im Vordergrund warten; währenddessen etwas anderes, ohne dasselbe Thema anzufassen.
- **Fortsetzen oder neu starten (gemessen 10.10.2026, `daniel-zum-abarbeiten/berichte/grundstock-tokens.md`, 353 Agenten):** Ein neuer Agent kostet ≈44k Input-Äquivalente (Anlauf ≈70k, halb aus Cache). Fortsetzen per `SendMessage` kostet ≈8k, solange die letzte Anfrage des Agenten **höchstens 5 Minuten** zurückliegt; danach ≈135–218k, weil sein ganzer Kontext neu in den Cache geschrieben wird. Faustregel: Folgeauftrag zum selben Thema innerhalb von 5 Minuten fortsetzen, sonst neuer Agent mit einer „Bekannt“-Zeile. Neues Thema immer neuer Agent.
- **Schlanke Agententypen** `bauer`, `analyst`, `pruefer` (`~/.claude/agents/`, seit 10.10.2026, wirken ab Sitzungsstart) statt `general-purpose`: nur die nötigen Werkzeuge, kein Skill-Werkzeug (Skills als Datei lesen). Rechercheur bleibt `general-purpose` (Websuche).

## Kosten und Messgröße
